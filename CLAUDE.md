# CLAUDE.md — instructions for Claude Code in this repo

## Project
Portfolio project (data analyst, target: Swiss job market). Product: a forecast of monthly hotel
overnight stays by canton, origin market and resort type (luxury vs mid-range), 1 to 12 months ahead,
for seasonal pricing and seasonal staffing, with the Swiss franc as the key explanatory variable
(how much it moves the forecast). FX analysis serves the forecast: it designs the features.
See `ROADMAP.md` for sprints and `data/README.md` for sources and data quirks. Read both before starting any task.

## Repo layout
- `data/raw/` — original downloads. **Never edit, rename or overwrite.**
- `data/processed/` — generated by code only. Rebuild with `python src/load_data.py`.
- `src/` — reusable Python modules (loading, features, models). No notebooks logic duplicated here.
- `sql/` — DuckDB SQL views, one file per view, numbered (`01_yoy.sql`, ...).
- `notebooks/` — numbered analysis notebooks (`01_eda.ipynb`, `02_fx_effect.ipynb`, `03_forecasting.ipynb`). They import from `src/`.
- `reports/figures/` — exported charts (PNG/SVG) used in the README.
- `tests/` — pytest unit tests on small synthetic data (run in CI on every push and PR).
- The dashboard lives in Looker Studio (tables exported to BigQuery by `src/export_bq.py`); no dashboard folder in the repo.

## Data conventions (non-negotiable)
- Tidy long format: one row = date × geo × origin × indicator. Columns: `date, geo, level, origin, indicator, value, currency`.
- FX = CHF per 1 unit of foreign currency. A **falling** value means the franc **appreciates**.
- Exclude Mar 2020 – Dec 2021 (covid) when estimating FX effects. Keep it in plots, shaded.
  Year-over-year estimates also exclude 2022 (base months in covid): use `features.yoy_uses_covid`.
- Commune level: compare **Germany vs Switzerland only** (other markets are too small, see ROADMAP notes).
- Excluded origins: India (no FX series), United Arab Emirates (series starts 2011, tiny volume).

## Modelling rules
- Forecast target: 49 series (7 cantons x 7 origin markets) + the total of each of the 8 paired resorts. Horizon 1–12 months (1–6 also tested against an FX noise floor in notebook 04; 7–12 validated like Sprint 3A in notebook 05).
- Time-based validation only (`TimeSeriesSplit` / rolling origin). Never a random train/test split.
- Always report a seasonal-naive baseline (same month last year) next to any model.
- Direct strategy, one model per horizon h (1–6): FX features must be lagged **≥ h months** (known at the forecast origin).
  FX after the forecast origin enters only as scenarios, never as a model input.
- Anything estimated from the data (change points, regimes) is re-estimated inside each training window: no look-ahead.
- Main metric: **WAPE** (sum of absolute errors / sum of actuals), with and without FX features, overall and in peak-season months;
  MAPE per series is secondary (it explodes on small, near-zero months)
  (peak season = each series' 3 highest months by average share of annual nights, 2013–2019, from `seasonal_profile`).
- Descriptive language for FX effects ("linked to"), never causal. Every number in notebook text comes from a printed output, or is asserted against the computed results (e.g. a "Summary check" cell).
- Out of scope: overbooking and nightly pricing (need daily, hotel-level data we do not have).

## Code style
- Python 3.11+, pandas, pathlib. Functions with docstrings; comments explain *why*, not *what*.
- Paths built from `ROOT = Path(__file__).resolve().parents[1]`, never hard-coded absolute paths.
- Every new processing step gets a check (`assert`) on row counts, nulls or totals.
- Charts: one message per chart, title states the takeaway, source line at the bottom.
- All code, comments, commit messages and README in **English**.

## Workflow

- Before finishing a task, run `python src/load_data.py` and any notebook touched, end to end.
